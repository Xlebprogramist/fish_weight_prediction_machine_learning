## Паспорт данных

Единица наблюдения — одна рыба. Пропусков, дубликатов строк, нулевых и
отрицательных значений в `fish_participant.csv` нет (проверяется тестами
`tests/test_data.py`). Групп (ферма, партия, улов) и временных меток в наборе
нет.

| Поле | Тип | Единицы / формат | Роль | Пропуски | Диапазон / словарь (фактический) | Источник | Что проверено |
|---|---|---|---|---|---|---|---|
| `Species` | категория | одна из 7 строк | признак; поле стратификации разбиения | нет | Perch 39, Bream 24, Roach 14, Pike 12, Smelt 10, Parkki 8, Whitefish 4 | ручная запись вида | нет пустых строк и лишних пробелов; редкий вид Whitefish (4) |
| `Weight` | число | граммы | **целевая переменная** | нет | 5.9 … 1550 | взвешивание | > 0; не вычисляется из других полей (иначе утечка) |
| `Length1` | число | см | признак | нет | 7.5 … 56.0 | измерение (вертикальная длина по документации Kaggle) | > 0; `Length1 ≤ Length2` |
| `Length2` | число | см | признак | нет | 8.4 … 60.0 | измерение (диагональная длина) | > 0; `Length2 ≤ Length3` |
| `Length3` | число | см | признак | нет | 8.8 … 64.0 | измерение (поперечная / полная длина) | > 0; корреляция с `Length1` 0.991 |
| `Height` | число | см | признак | нет | 1.74 … 18.96 | измерение | > 0 |
| `Width` | число | см | признак | нет | 1.05 … 8.14 | измерение | > 0 |
| `V_proxy` | число, производное | см³ | признак (только в экспериментах E4) | нет | `Length3 · Height · Width` | вычисляется в пайплайне | не использует `Weight`; дублирует информацию длин |

**Неопределённости.** Единицы взяты из описания набора на Kaggle и проверены
только косвенно: щука длиной 64 см и массой 1550 г, корюшка 10.8 см и 6.7 г —
это физически правдоподобно для сантиметров и граммов. Точный способ измерения
трёх длин в источнике описан кратко; гипотеза «`Length3` — полная длина»
согласуется с тем, что `Length1 ≤ Length2 ≤ Length3` во всех строках.

**Физический смысл.** Масса пропорциональна объёму тела, то есть примерно
кубу линейного размера. Отсюда ожидаемая нелинейность зависимости `Weight` от
длин и обоснование для логарифмов и для `V_proxy`.

**Строка 13** (Pike, 1550 г, L3 = 64 см) — выброс по правилу IQR для `Weight`.
Исходный проект удалял её по жёсткому индексу до разбиения. В ЛР2 она
сохранена: геометрия согласована, это крупная особь, а не ошибка измерения.
Удаление выбросов по IQR вынесено в параметр `train.drop_weight_outliers_iqr` и
применяется только к обучающей части (эксперимент `E1_esharma3`).

## Разбиение

Тестовая выборка заморожена **до** выбора признаков и гиперпараметров командой

```bash
python -m src.make_split --config configs/base.yaml
```

| | |
|---|---|
| Правило | `train_test_split(test_size=0.2, random_state=42, stratify=Species)` по позициям строк `fish_participant.csv` |
| Размер | train 88 / test 23 |
| Тест по видам | Perch 8, Bream 5, Roach 3, Smelt 2, Parkki 2, Pike 2, Whitefish 1 |
| Индексы | `data/split.json` вместе с SHA-256 данных; `src.data.load_split` отказывается работать, если файл данных изменился |
| Внутри train | `RepeatedKFold(n_splits=5, n_repeats=3, random_state=42)` — выбор моделей и гиперпараметров |

**Почему не GroupKFold.** В наборе нет признака, объединяющего строки одной
партии, фермы или улова; каждая строка — отдельная рыба. Разбиение по группам
невозможно и не требуется. Временной метки тоже нет, поэтому разбиение
«прошлое → будущее» не применяется.
